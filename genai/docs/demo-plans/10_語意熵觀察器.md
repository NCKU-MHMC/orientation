# Demo 10:語意熵觀察器

**課程位置** 附錄 D;第二堂⑤ AR 段(虛假前提)可借用
**展示的單一概念** predictive entropy 被 tokenization/措辭干擾;semantic entropy
先按語意聚類再算熵。

## 畫面與互動
- 選一題(含正常前提與虛假前提兩類預設),顯示預存的 20 個模型回答
- 左欄:predictive entropy(逐 token logprob 直接算)
- 右欄:回答經語意聚類後的簇視覺化(同簇同色),semantic entropy 讀數
- 控制:語意相似度門檻滑桿,拉動時簇即時合併/分裂,semantic entropy 同步變
- 對照列:「巴黎」「法國巴黎」「首都是巴黎」被聚進同簇的示範題

## 實作要點(成本 0,Tier 2 + Tier 1)
- 取樣(Tier 2):課前以 Ollama 對每題取 20 個回答並存逐 token logprob → JSON
- 聚類(Tier 1):瀏覽器內以 Transformers.js 跑 all-MiniLM-L6-v2(約 23MB)現場算
  embedding,cosine 相似度 + 門檻式凝聚聚類;離線備援為 JSON 內附預計算 embedding
- **方法備註(必須顯示於 UI)**:Kuhn et al. (2023) 原法以雙向蘊涵判定語意等價,
  本 demo 以 embedding 相似度近似,是簡化版
- 前端約 300 行

## 課堂展示腳本(2 分鐘)
1. 正常前提題:回答措辭各異但同義,predictive entropy 高、semantic entropy 低(40s)
2. 虛假前提題:回答語意真的分歧,兩個熵都高;兩題對照即「措辭雜訊 vs. 真不確定」(40s)
3. 拉門檻滑桿:簇合併分裂,semantic entropy 跟著跳。「語意等價的定義本身是
  這個量測的自由度」(30s)

## 三方討論紀錄
- E:雙向蘊涵要跑 NLI 模型多次,瀏覽器內成本高。**決議:embedding 近似 + 門檻聚類,
  UI 明示與原論文方法的差異。**
- P:堅持方法備註不可省略,否則學生會以為這就是 semantic entropy 的定義。
  **決議:列驗收必要項。**
- D:門檻滑桿原是工程參數,P 指出它恰好展示「語意等價定義是自由度」,升格為
  展示重點而非隱藏選項。**決議:採納,寫入腳本第 3 步。**
- E:embedding 現場計算約 1–2 秒/20 句,可接受;離線備援照常提供。**決議:雙軌。**

## 驗收標準
- 兩類預設題的熵對比方向正確;門檻滑桿行為連續合理
- 斷網時(預存 embedding)功能完整;方法備註常駐可見
