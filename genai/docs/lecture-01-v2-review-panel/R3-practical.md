## 總體評價

這份簡報的**教學設計骨架是我近年看過最紮實的一份**:一條軸貫穿全課、開場失敗現場在 ⑦ 回收、作業 A 逼學生把自己的題目形式化、作業 B 用同一份資料在三個模型上做對照。這些都不是裝飾,是可驗收的設計。

但**作業 B 目前寫不出來**。我逐項打開四個 demo 的 HTML 原始碼確認過:作業 B 對 Flow Matching demo 提出的觀察要求(記錄積分步數)在介面上不存在,積分步數是原始碼裡的 `const STEPS = 28`,從未顯示;作業 B 要求的三個必用詞之一「逐點評分的盲點」,其唯一可觀察的證據(GAN 的 D 地景疊圖)在作業指示裡沒有被要求打開;Flow Matching demo 有**兩個**分布下拉選單,作業只說「切到中心偏移混合」,學生有一半機率切錯那一個,切錯就得到完全不同的圖。

好消息是:這些全部是**指示文字的問題,不是 demo 的問題**。demo 本身做得很好——尤其三個 demo 的 `mixtureOff` 資料集在 `gan-2d-interactive.html:203`、`vae-2d-interactive.html:199`、`flow-matching-2d-interactive.html:212` 的參數(r=3.0、σ=0.12)**完全一致**,連畫布範圍 `VIEW=6.6` 都對齊了。這是刻意做的跨 demo 可比性,而作業 B 的整個設計就靠它成立。修法幾乎都是在作業那三頁多加一兩句話。

判定:**作業 B 在修正前不應發下去**。作業 A、投影片本體、demo 本身都可以照現況上。

## 問題清單

### [CRITICAL] 1 · 作業 B 要求記錄的「積分步數」,Flow Matching demo 從頭到尾不顯示

**位置**:作業 B,`lecture-01-choose-a-ruler-v2.md:1751-1754`;`public/demos/flow-matching-2d-interactive.html:178`

**問題**:作業 B 的第三格寫「Flow Matching 2D / 記錄所使用的積分步數」。這個量在 demo 介面上**不存在**——它是原始碼裡的常數,既沒有滑桿可調,也沒有任何地方把數字印出來。學生唯一看得到的數字叫 `step`,那是**訓練迭代數**,會一路跑到幾千。可以預期絕大多數人會把「step 4200」當成積分步數交上來,而這剛好是整份作業裡最容易被誤答又最不容易被發現的一格。

**證據**:
```
flow-matching-2d-interactive.html:178
const H = 64, BS = 256, P = 240, STEPS = 28, FG = 15;   // 粒子數、積分步數、向量場格數
```
全檔搜尋 `STEPS`,出現在 178、183、231、280、282、296、354 行,**全部在 `<script>` 內**。readout 區(`fm:116-119`)只有:
```html
<span>step <b id="stepVal">0</b></span>
<span class="r-loss">FM loss <b id="lossVal">–</b></span>
```

**建議**(擇一,由易到難):
- **最省事**:把作業文字從「記錄所使用的積分步數」改成「本 demo 的積分步數固定為 **28**(寫在原始碼裡,介面不顯示)。請說明:為什麼 VAE 與 GAN 那兩格不需要填這個欄位?」——這樣不但修掉了不可執行,還把它變成一個更好的問題,直接命中三難裡「取樣速度」那個頂點。
- **次之**:在 demo 的 readout 加一格 `<span>積分步數 <b>28</b></span>`(純靜態文字,不必改邏輯)。
- **最理想但最貴**:加一個步數滑桿(8/16/28/64),讓學生真的看到步數少時粒子落點變糟。這才是作業原本想要的教學效果,但要動 `recomputeTraj()` 的快取尺寸。

### [CRITICAL] 2 · Flow Matching demo 有兩個分布選單,作業只說「切到中心偏移混合」;且沒說要把 t 拉到 1 才截圖

**位置**:作業 B,`lecture-01-choose-a-ruler-v2.md:1735`(「把三個互動 demo 都切到『中心偏移混合』這組資料」)、`:1751-1754`;`flow-matching-2d-interactive.html:81-103`

**問題**:兩個獨立的可執行性缺口疊在同一格上,兩個都會讓截圖作廢。

1. **切錯選單**:FM demo 有「來源分布 p₀」與「目標分布 p₁」兩個下拉,**兩個都有「高斯混合 ×6(中心偏移)」這個選項**。作業說「切到中心偏移混合」而沒說切哪一個。正確做法是保持來源 = 高斯 N(0,I)(預設值)、把**目標**改成中心偏移混合;但如果學生改的是來源,就變成「中心偏移混合 → 雙月」,得到一張跟 VAE/GAN 完全無法對照的圖,而學生沒有任何線索知道自己錯了。

2. **截圖時機**:預設「自動播放」是勾選的,t 會不停循環。粒子只有在 t=1 時才是生成樣本。一張隨機時刻的截圖拍到的是半路上的粒子雲——那不是任何模型的輸出,拿它跟 VAE/GAN 的收斂圖並排比較是沒有意義的。

**證據**:
```html
flow-matching-2d-interactive.html:81-99
<select id="srcSel"> … <option value="mixtureOff">高斯混合 ×6(中心偏移)</option> …
<select id="tgtSel"> … <option value="mixtureOff">高斯混合 ×6(中心偏移)</option> …
flow-matching-2d-interactive.html:104
<label class="toggle ctrl"><input type="checkbox" id="autoT" checked> 自動播放</label>
```
主迴圈:
```js
flow-matching-2d-interactive.html:523-527
if(autoT){ flowT += 1/240; if(flowT>1.25) flowT=-0.15; … }
```
→ 約 5.8 秒一輪,只有約 1 秒鐘 t 被 clamp 在 1.00。隨手截圖命中 t=1 的機率約 17%。

面板說明本身已經寫對了(`fm:126`「t=1 時的粒子就是**生成樣本**」),只是作業沒把它轉成指令。

另可參考:demo 自己的建議流程 `fm:167` 寫的是「1) 高斯 → **中心偏移混合**」——**demo 作者的原意就是我上面說的那個組合**,作業只是漏了把它寫全。

**建議**:把作業 B 的 FM 那一格改寫成逐步指令:
> **Flow Matching 2D**
> 來源分布 p₀ 保持「高斯 N(0,I)」,**目標分布 p₁** 改成「高斯混合 ×6(中心偏移)」。
> 按「開始訓練」,等 loss 曲線走平後按暫停,**取消勾選「自動播放」,把「時間 t」滑桿拖到 1.00** 再截圖。

同時把 L1735 那句總指示改成「把三個 demo 的**資料集/目標分布**都切到『高斯混合 ×6(中心偏移)』」,避免「中心偏移混合」這個簡稱(見 MINOR-1)。

### [CRITICAL] 3 · 作業 B 規定必須用到「逐點評分的盲點」,但沒有任何一個步驟讓學生看到它

**位置**:作業 B,`lecture-01-choose-a-ruler-v2.md:1746-1749`(GAN 那一格)與 `:1765`(三個必用詞);`gan-2d-interactive.html:103`

gan-2d-interactive.html:103

最後那個問句就是「逐點評分的盲點」的操作型定義,學生答完自然接得回機制,評分重點 ③ 也才有東西可評。

### [MAJOR] 1 · 「訓練至穩定」「收斂後」對 GAN 沒有定義,作業結果不可重現

**位置**:`lecture-01-choose-a-ruler-v2.md:1735`(「各截一張**收斂後**的圖」)、`:1748`(「**訓練至穩定**」)

**問題**:這兩個詞對 VAE 和 FM 還算可判定(loss 走平),對 GAN 則自我矛盾。demo 自己的說明就寫著損失曲線「不會單調下降」、「震盪是常態」,而且會 mode hopping——覆蓋的 mode 數會隨時間變。所以「記錄覆蓋到幾個 mode」的答案取決於學生按暫停的那一秒,不同人會交出 2、3、4 甚至 6,彼此無法對照,而作業 B 的整個價值就在對照。

**證據**:
```
gan-2d-interactive.html:139  對抗訓練是賽局而非最佳化單一目標:兩條曲線互相拉扯、震盪是常態。健康的訊號不是 loss 變低…
gan-2d-interactive.html:145  訓練一陣子後,白點(與生成器網格)可能只覆蓋 6 群中的 2~3 群,甚至在幾群之間來回跳動(mode hopping)
```
另外全檔無 RNG 種子(`gan:185` 起一路用 `Math.random()`),每次重整都是新的軌跡。

**建議**:把三格的停止準則統一改成**明確的 step 數**——`step` 讀數三個 demo 都有(`gan:105`、`vae:81`、`fm:117`),是現成可用的客觀錨點:
- VAE:「β 保持 1,跑到 step ≥ 3000 後暫停截圖」
- GAN:「跑到 step ≥ 3000 後暫停截圖;若此時仍在 mode hopping,請照實寫下『第 3000 步覆蓋 N 群』並註明有跳動」
- FM:「跑到 step ≥ 3000 後暫停」

順帶把「mode hopping 導致答案會變」本身變成 B 的一個觀察點,而不是一個 bug——這比「訓練至穩定」教得更多。

### [MAJOR] 2 · L1298 的修辭問句與 L1307 的答案自相矛盾,學生會學到錯的結論

**位置**:`lecture-01-choose-a-ruler-v2.md:1296-1310`

## 跨領域遷移的評估

任務要求判斷投影片宣稱的六條遷移是紮實還是牽強。我的判斷:**四條紮實、一條偏薄、一條過度宣稱**。

**紮實(可以直接讓學生據以行動)**

- **confidence 校準**(L112 表、L705-732、L915-949)。這條是六條裡最好的。它不只說「有關」,還給出了具體的錯誤來源(tokenization 切碎機率、序列 likelihood 的長度偏誤)與具體的修法(用參考模型正規化成 likelihood ratio,把「這句話本身有多罕見」扣掉)。備註 L952「先把量測工具修好,再談相關性」是一句可以立刻改變學生下週工作內容的建議。

- **虛假前提檢測**(L121、L885-905)。「$p(y\mid x)$ 良好定義」與「$x$ 值得被回答」是兩件事,而 forward KL 訓練出的模型結構上就沒有「拒絕」這個選項——這是機制層級的解釋,不是類比。玉山第三個火山口那個例子選得很好。備註 L910 還給了可跑的 benchmark。

- **LLM-ASR**(L123、L743-777 + 備註 L774)。$p(\text{text}\mid\text{audio})\propto p(\text{audio}\mid\text{text})p(\text{text})$ 是該領域的標準分解,而「換 LM 之後 LM weight 這個超參數要能移植,尺度就得統一成 bits per byte」是一個具體、可驗證、而且學生真的會踩到的坑。

- **情感支持對話**(L120、L1113、L1568-1578)。「RLHF 用的是 reverse KL 方向,這是對齊後多樣性塌陷的直接來源」,加上 L1575-1576「方向是**可選的**」——這條給了學生一個真正的設計槓桿,而不只是一個診斷。β-VAE 的 β 與 RLHF 的 β 是同一個角色(L1113)這個連結也是對的,而且回收得很乾淨。

**偏薄**

- **prompt engineering**(L118)。「選擇條件變數 $c$,操控 $p(y\mid c)$;只換條件,不動目標函數」——這句話正確,但它給學生的是一個**位置**而不是一個**工具**:知道自己在軸上不動,接下來要做什麼?A2 的提示(L1725-1726)甚至直說「你的 A2 是『我沒有目標函數,我在動 c』」。誠實,但這一格在驗收清單裡等於空白。
  **建議**:把這一格接到本課真正能給的東西上——第 ⑦ 段預告的「推論時滑動」那一列(SpectrumAxis 的第二列:溫度、top-p、CFG)才是 prompt 組的著力點。可以在 L118 那格的「在軸上的位置」改成「只換條件,不動目標函數 → **你的槓桿在第 2 列(下堂課)**」,把空白轉成一個明確的期待。

**過度宣稱**

- **memory agent**(L119、L836-838、備註 L852-854)。投影片說「memory agent 的長對話漂移」來自 exposure bias,備註更強:「長對話漂移**不是** context window 的問題,**是**訓練目標從來沒看過自己生成的長前綴」。exposure bias 這條因果本身是對的,但把它斷言成長對話漂移的**唯一或主要**成因,對做 memory agent 的學生是誤導:
  - 多數 memory agent 建在**凍結的 API 模型**上,學生不訓練任何東西,exposure bias 對他而言不是可操作的變因;
  - 長對話漂移在實務上更常來自檢索召回、上下文組裝順序、摘要壓縮的資訊損失,以及 L119 那格自己就寫對了的「長 context 下 $p(\text{task}\mid\text{prompt})$ 被稀釋」——**表格那一格比備註那句話準確**;
  - 「不是 context window 的問題」這種二選一的斷言,恰好會讓學生停止調查真正可控的那一半。

  **建議**:備註 L852-854 改成非排他的說法:「長對話漂移至少有兩個來源:一是條件被稀釋(L119 那格),那是你**現在就能動**的;二是訓練目標從沒測量過模型自己生成的長前綴,那是 exposure bias,解釋了為什麼**即使檢索完美**漂移仍然存在——但那一半你得換模型或做後訓練才動得到。」這樣既保住了洞見,又不會把學生推離他真正能改的東西。
